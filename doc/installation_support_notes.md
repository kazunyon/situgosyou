# インストール相談の引継ぎ記録（2026-10-01）

## 利用者の希望

- PCとスマホのPWAを維持し、同じメモを自動同期する。
- 第三者は自分専用のSupabaseを用意する。作者のSupabase設定を組み込まない。
- FirebaseとBrevoは希望していない。確認コードのメール送信はGmailを使う。
- 追加ソフトのインストール・手入力・設定画面を探す操作を減らす。
- 左手だけで操作する。クリック・タップ・右クリックの貼り付けを優先する。
- 画面ごとに、実際に見えている項目の位置を示し、短い順番で案内する。

## 今回発生した問題と解決

1. Supabase管理画面のURLをProject URL欄へ貼り付けていた。修正版は接続用URLへ変換する。
2. 以前の端末内版と同じリポジトリ名で止まった。新規同期版は別の公開先を作成した。途中の再試行は同じ設定・同じ公開先を使う。
3. GitHub APIのHTTP/2 REFUSED_STREAMで止まった。子プロセスのGitHub CLIだけHTTP/1.1に変更済み。HTTPSの検証は維持。
4. メールのリンクを開くと無効・期限切れ、GitHub Pagesのルートで404になった。アプリは確認コード入力を使う。
5. Supabaseの画面ではCustom SMTP未設定のままメール本文を編集できなかった。先にSMTPを保存してから、Magic link or OTPとConfirm sign upのSourceを設定する。
6. Gmailで535 Username and Password not acceptedになった。再設定用メールアドレスと、アプリパスワードを作ったGoogleアカウントを混同していた。Sender email addressとUsernameを実際の送信用Googleアカウントに合わせて解決。
7. Supabaseから8桁のコードが届いた。以前のアプリは6桁のみ。Email → Email OTP lengthを6に合わせ、利用者から「Supabaseのエラーは消えた」と報告された。
8. 今回の修正版アプリは6～10桁のコードに対応し、8桁のままでも入力できる。メール本文には `{{ .Token }}` を使う。

## 現時点の公開先と確認範囲

- 利用者が操作している同期版： https://kazunyon.github.io/kotoba-memo-sync/
- 利用者から確認されたのは、今回のSupabaseエラーの解消。PC・スマホの双方向同期の実機確認は、まだ成功報告がない。
