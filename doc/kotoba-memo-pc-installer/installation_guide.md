# ことばメモ インストール手順書：提供時の参考コピー

このファイルは提供フォルダーに含まれていた手順書の参考コピーです。導入時は [ことばメモ インストール手順書（正式な案内）](../installation_guide.md) を参照してください。[参考用ツールのREADMEへ戻る](README.md)。

## 今回の修正版：最短で使う方法

**公開済みのアプリを使う人は、ZIPや追加ソフトをインストールする必要はありません。** PCとスマホで同じアプリの公開URLを開き、同じメールアドレスへ届く確認コードでログインします。PWAとしてスタートやホーム画面へ追加する操作は任意です。

公開を準備する人だけ、PCツールを使います。ZIPを展開したら、まず **Setup.html** を開いてください。ブラウザでSupabase・Gmailの準備を順番に案内します。管理画面のURLも貼り付けられ、各設定画面へ直接移動できます。その後 **Start-Installer.cmd** で新規公開します。

今回の修正版アプリは、確認コードの **6～10桁** に対応しています。Supabaseが8桁を送る設定でも使えます。以前の6桁用アプリは、Authentication → Sign In / Providers → Email → 一番下の Email OTP length を6に設定して使います。

PCツールは、検証できた前回の入力をこのPCの `%LOCALAPPDATA%/KotobaMemoInstaller/preferences.json` に保存し、次回復元します。GitHub名・アプリ名・自分のProject URL・公開用キーが含まれます。SMTPパスワードやGoogleアプリパスワードは保存しません。共有PCでは、自分のWindowsアカウントで操作してください。

### Gmailを使う準備：今回の画面に合わせた順番

1. Googleの2段階認証を有効にし、送信用アカウントの [アプリパスワード画面](https://myaccount.google.com/apppasswords) で「ことばメモ」用を作ります。
2. **通知を受け取ったメールアドレスではなく、アプリパスワードを作ったGoogleアカウントのアドレス**を確認します。セキュリティ通知のコピーが再設定用メールへ届く場合があります。
3. 自分のSupabaseの Authentication → Emails → SMTP Settings を開きます。Enable custom SMTPをオンにします。
4. Sender email address と Username の両方に、手順2の同じアドレスを入れます。Sender nameは自分のアプリ名、Hostは `smtp.gmail.com`、Port numberは `465`、Minimum interval per userは `60` です。
5. PasswordにはGoogleで作った16文字のアプリパスワードを貼り付け、Save changesをクリックします。通常のGoogleパスワードは入力しません。
6. Templates → Magic link or OTP → BodyのSourceを開きます。下の本文へ入れ替えて保存します。Confirm sign upにも同じ本文を保存します。

```html
<h2>ことばメモの確認コード</h2>
<p>確認コード：{{ .Token }}</p>
<p>この数字を、ことばメモの確認コード欄に入力してください。</p>
```

7. アプリで確認コードを送信し、新しく届いたメールの数字を全部入力します。修正版では数字を6桁に切り詰めません。

Gmailの送信にはアカウント側の制限があります。アプリパスワードを利用できない組織アカウントなどでは、管理者への確認が必要です。送信用アカウントと、アプリにログインする利用者のメールは別でも構いません。[Google公式のアプリパスワード説明](https://support.google.com/accounts/answer/185833?hl=ja)、[Supabase公式のGoogle SMTP説明](https://supabase.com/docs/guides/troubleshooting/using-google-smtp-with-supabase-custom-smtp-ZZzU4Y)

**535 Username and Password not accepted** の場合は、Sender email address・Username・アプリパスワードが同じGoogleアカウントに対応しているか確認します。一般的な「Error sending magic link email」だけで原因を決めず、SupabaseのLogs → Authで最新のERROR行を開き、error欄を読みます。

今回の相談経緯と確認範囲は [引継ぎ記録](installation_support_notes.md) に保存しました。利用者からSupabaseエラーの解消が報告されています。双方向同期の実機確認は引き続き必要です。ZIPの修正だけでは、すでに公開したサイトは更新されません。既存公開先で設定を直して動作している利用者は、そのまま利用できます。

この版は、第三者が **自分自身のSupabaseプロジェクト** を用意し、PCとスマートフォンで同じメモを使うための手順です。作者のSupabase設定はツールに入っていません。Firebaseは使いません。

操作は左手だけで進められるクリック・タップ中心です。PCの貼り付けは **右クリック → 貼り付け**、スマホは入力欄の **長押し → ペースト** を使えます。複数キーの同時押しは必要ありません。

## 1. 最初に用意するもの

### 公開を準備する人

| 必要なもの | 用途 |
| --- | --- |
| Windows 10・11のPC | PCインストールツールを実行します。 |
| EdgeまたはChrome | GitHubへのログインとPWAのインストール。 |
| 自分のGitHubアカウント | 新しい公開リポジトリとGitHub Pagesの作成。 |
| 自分のSupabaseアカウント | 自分専用の新しいプロジェクトの作成。 |
| Supabase Project URL | 自分の `https://プロジェクトID.supabase.co`。 |
| Supabase Publishable key | `sb_publishable_`で始まるブラウザ用公開キー。旧anonキーも対応。 |
| メールを受信できるアドレス | PCとスマホで同じアドレスを使います。 |
| 確認コードを送信するメール設定 | Supabaseで設定。一般利用者への送信には自分のSMTP設定が必要。 |
| 更新版PCツールのZIP | スマホ用ページと初期設定SQLを含みます。 |
| インターネット接続 | 公開、初回インストール、ログイン、同期。 |

Git・Node.jsをPCへインストールする必要はありません。GitHub用ツールがない場合、PCツールが公式のGitHub CLIを取得します。

**DBパスワード、`service_role`、`sb_secret_`、Supabase管理用トークンは、このツールへ入力しません。** Publishable keyはWebアプリに含まれる公開用の値です。メモへのアクセスはログインとデータ分離設定で制限します。[Supabaseのキーの公式説明](https://supabase.com/docs/guides/getting-started/api-keys)

### インストールして使う人

- PCはEdgeまたはChrome。
- iPhone 14を含むiPhoneはSafari、AndroidはChrome。
- 公開を準備した人から受け取ったアプリのHTTPS URL。
- PCとスマホの両方で確認コードを受信できる、同じメールアドレス。
- 初回のインターネット接続。

同じ公開先を使うスマホに、別のSupabaseプロジェクトを作る必要はありません。APIキーも再入力しません。公開準備をしない利用者はGitHub・Supabaseの管理アカウントを作る必要はありません。

## 2. この構成でできること

| 役割 | 使用するもの |
| --- | --- |
| PWA本体の配信 | 自分のGitHub Pages |
| PCとスマホの共有保存先 | 自分のSupabase |
| 本人の確認 | メールの確認コード（6～10桁） |
| 通信できない間の保存 | 各端末のブラウザ内の保存領域 |

自分でアプリ用サーバーを設置・管理せずに使います。配信と共有保存にはクラウドを使用します。

オンラインで起動・ログインすると、同じ公開先・同じSupabase・同じメールアドレスのPCとスマホで、メモ、カテゴリ、メモ内の画像を共有します。開いているアプリには変更通知で反映し、通知を取り逃した場合も、画面へ戻ったときや約15秒ごとの確認で最新の内容を取得します。閉じている間に画面を更新するものではありません。

一度オンラインで起動・ログイン・データ取得を済ませた端末では、通信できない間も保存済みメモを利用できます。変更は端末に残して **未送信** と表示し、オンラインでアプリを開くと送信を再開します。**未送信の間にアプリやサイトデータを削除しないでください。**

同じ項目を両端末で変更した場合は、黙って上書きせず、利用者にどちらの内容を使うか選んでもらいます。

## 3. 自分のSupabaseを準備する

### 3-1. 専用プロジェクトを作る

1. PCで [Supabase管理画面](https://supabase.com/dashboard) を開き、自分のアカウントでログインします。
2. **New project** をクリックします。
3. 自分の組織を選び、プロジェクト名を入力します。例：`hanako-kotoba-memo`。
4. 作成画面で求められたDBパスワードを設定し、安全な場所へ保存します。このパスワードはインストールツールに入力しません。
5. リージョンを選び、作成が完了するまで待ちます。

既存アプリのテーブルが入ったプロジェクトではなく、新しい専用プロジェクトを使います。同梱SQLは別の公開ポリシーがある場合、既存設定を勝手に変更せず停止します。

### 3-2. PCツールを開く

1. PCツールのZIPを保存します。
2. ZIPを右クリックし、**すべて展開** を選びます。
3. 展開先の **Start-Installer.cmd** をダブルクリックします。
4. **GitHubユーザー名**、**公開用リポジトリ名**、**アプリの表示名** を入力します。

ソース全体のZIPでは **installer → pc → Start-Installer.cmd** を開きます。ツール用ZIPは、同梱の `app-template` と `mobile` フォルダーも展開した状態で使います。

### 3-3. Project URLと公開キーを入力する

1. 自分のSupabaseプロジェクトの **Connect** または **Settings → API Keys／Data API** で、**Project URL** と **Publishable key** を表示します。
2. Project URLをコピーし、PCツールの **自分のSupabase Project URL** へ右クリックで貼り付けます。
3. Publishable keyをコピーし、PCツールの **Supabase Publishable key** へ貼り付けます。

旧anonキーは、同じプロジェクトのものだけを使います。管理者用キーは入力チェックで拒否します。現在は標準の `https://プロジェクトID.supabase.co` のURLに対応しています。

### 3-4. 初期設定SQLを実行する

1. PCツールの **自分のSupabaseに使う初期設定SQLをコピー** をクリックします。
2. 自分のSupabaseプロジェクトで **SQL Editor** を開きます。
3. 新しいクエリ欄へ **右クリック → 貼り付け** します。
4. **Run** をクリックします。
5. エラーなく完了したことを確認します。

SQLはメモ・カテゴリ・同期用の版管理を作成し、本人のデータだけを読み書きできる設定と変更通知を準備します。同じ専用プロジェクトで再実行できます。作者のプロジェクトへ実行しないでください。

必要であれば、別のクエリで次を実行します。

```sql
select public.kotoba_installer_status();
```

結果が `schemaVersion: 2`、`rls: true`、`realtime: true`、`ownerPolicies: true` になることを確認します。PCツールも公開前にこの状態を確認します。

### 3-5. メールの確認コードを設定する

1. 自分のプロジェクトの **Authentication** を開きます。
2. 認証プロバイダーの **Email** でメールによるログインを有効にします。
   新しい利用者の初回ログインを受け付ける場合は、Sign In / Providers の **Allow new users to sign up** も有効にします。既存の利用者だけで使う場合は、登録を許可する範囲を自分で決めます。
3. メール確認を有効にします。修正版は6～10桁に対応しています。以前の6桁用アプリを使う場合だけ、OTPの長さを **6桁** にします。
4. **Email Templates** の **Confirm signup** と **Magic Link** の本文に、次のように確認コードを表示する設定を保存します。

```html
<h2>ことばメモのログイン</h2>
<p>確認コード：{{ .Token }}</p>
```

初回の登録と2回目以降のログインで使うテンプレートが異なるため、両方を設定します。このアプリはメールのリンクを押す方式ではなく、メールに届く数字を入力する方式です。[公式のメールOTP手順](https://supabase.com/docs/guides/auth/auth-email-passwordless)

Supabaseの標準メール送信は、プロジェクトの組織メンバーのアドレスへの試用に限られ、送信回数にも制限があります。**ほかのメールアドレスや一般利用者が使う場合は、Custom SMTPに自分のメール送信サービスを設定します。** SMTPのホスト・ポート・ユーザー名・パスワード・送信者アドレスはSupabaseの管理画面へ入力し、このインストールツールへは入力しません。[公式のSMTP設定と制限](https://supabase.com/docs/guides/auth/auth-smtp)

組織メンバーのメールでPC・スマホの試用を行う場合も、短時間にコードを繰り返し送らず、メールが届くことを確認して進めます。運用時は自分のSMTP設定を準備します。

## 4. PCツールで公開する

1. PCツールで、入力したSupabaseの接続先と公開キーを確認します。
2. **自分の専用プロジェクトにSQLを実行し、メール認証を準備しました** にチェックします。
3. **1. GitHubにログイン** をクリックします。
4. ブラウザで確認コードを入力し、GitHub CLIを許可します。**確認コードをコピー** を使えます。
5. GitHubユーザー名がログイン中のアカウントと合うことを確認します。
6. **2. 自分の公開先を作成して、アプリを準備する** をクリックします。
7. **公開が完了しました** と表示されるまで待ちます。

ツールはSupabaseの準備状態を確認してから、自分のGitHubに新しい公開リポジトリを作成します。入力した表示名・公開パス・Supabase設定と同期対応アプリを配置してGitHub Pagesへ公開します。

作者の環境ファイル・Supabase設定・GitHub Secretsは引き継ぎません。入力されたブラウザ用公開キーはアプリに組み込まれます。公開完了はGitHubの公開処理、ページ、PWA設定、スマホ用ページ、Supabase接続先の識別設定まで確認できたことを示します。メール配信と実際のメモ同期は第8章で確認します。

公開URLは通常 `https://GitHubユーザー名.github.io/リポジトリ名/` です。例は実際の導入者の値に読み替えます。

```text
アプリ：https://hanako.github.io/hanako-memo/
PC案内：https://hanako.github.io/hanako-memo/install.html
スマホ案内：https://hanako.github.io/hanako-memo/mobile-install.html
```

## 5. PCで使う（PWA追加は任意）

1. PCツールの **3. ブラウザでアプリを開く（インストール不要）** をクリックします。ブラウザで使う場合は、下のログイン手順へ進みます。PWA追加を希望する場合は、公開URLの末尾に `install.html` を付けて開き、次の追加手順を行います。
2. EdgeまたはChromeで **このPCにインストール** をクリックします。
3. ブラウザの確認画面で **インストール** をクリックします。
4. Windowsの **スタート** から指定した表示名のアプリを起動します。
5. メール欄に自分のメールアドレスを入力します。
6. **確認コードを送る** をクリックします。
7. メールのコードを入力し、**コードを確認してログイン** をクリックします。
8. 自分のメールアドレスと同期状態が表示されることを確認します。

ボタンが使えない場合は、アドレスバーのインストールアイコンかブラウザのメニューを使います。すでに入っている場合はスタートから起動します。カテゴリがなければ **設定 → カテゴリを追加 → カテゴリを保存** を行います。

## 6. スマートフォンで使う（PWA追加は任意）

ブラウザで使う場合は、PCと同じアプリの公開URLをSafariまたはChromeで開き、同じメールアドレスでログインするだけです。以下はホーム画面へのPWA追加を希望する場合の手順です。

PCと **同じ公開先** の `mobile-install.html` を開きます。スマホへのZIPのダウンロード・展開は不要です。

### 6-1. スマホ用ツールの入力

1. AndroidはChrome、iPhoneはSafariでスマホ用URLを開きます。
2. **GitHubユーザー名**、**公開用リポジトリ名** を確認します。分かる項目は自動入力します。
3. **ホーム画面に表示したい名前** を入力します。
4. 自動入力された **Supabase Project URL** がPCと同じか確認します。
5. **PCでログインするのと同じメールアドレス** を入力します。
6. **使うスマホ** を選び、**2. 公開先を確認する** をタップします。
7. 別の公開先を指定した場合は **自分の公開先で続ける** をタップし、移動先で再確認します。メールは移動先でも入力します。メールアドレスを移動用URLへ含めません。

Project URLは確認用です。この画面だけでアプリの接続先を書き換えることはありません。異なる接続先にしたい場合はPC版ツールで新しい公開先を準備します。スマホへの公開キーの再入力は不要です。

### 6-2. iPhone 14を含むiPhone

1. **入力した名前をコピー → アプリを開く** をタップします。
2. Safariの **共有**（四角に上向きの矢印）をタップします。見えない場合はページメニューから **共有** を選びます。
3. 下へスクロールし、**ホーム画面に追加** をタップします。
4. 名前欄を長押しして **ペースト** を選びます。コピーできない場合は名前を入力します。
5. **ウェブアプリとして開く** がある場合はオンにし、**追加** をタップします。
6. ホーム画面の新しいアイコンから起動します。
7. **PCと同じメールアドレス**を入力し、届いた確認コードでログインします。

「ホーム画面に追加」がない場合は共有メニューの **アクションを編集** から追加します。[Appleの公式手順](https://support.apple.com/ja-jp/guide/iphone/iphea86e5236/ios)

Safariでログインしていても、ホーム画面から開いたアプリでログインを求められたら、その画面でログインします。ホーム画面の名前を変えてもアプリ内の見出しは公開時の名前です。

### 6-3. Android

1. **このスマホにインストール** が使える場合はタップします。
2. Chromeの確認画面で **インストール** をタップします。
3. ボタンが使えない場合は **アプリを開く → Chromeの︙ → ホーム画面に追加／アプリをインストール** を使います。
4. ホーム画面またはアプリ一覧から起動します。
5. **PCと同じメールアドレス**を入力し、届いた確認コードでログインします。

AndroidのPWA名は公開時のアプリ名です。異なる希望名を入力した場合は、実際の名前と変更方法を表示します。アプリ内ブラウザではなくChromeで開きます。

## 7. 旧端末内版のメモを最初に移す

Supabase設定を追加しても、旧版のPC内メモが自動でアップロードされるわけではありません。

1. 登録内容が入っている **旧PC版** を開きます。
2. **設定 → バックアップ** でJSONファイルを保存します。
3. 同期版のPCアプリを開き、自分のメールでログインします。
4. 初期の共有データが空であることを確認します。
5. **設定 → バックアップを戻す** で旧版のJSONを選びます。
6. 件数と内容を確認して復元します。
7. **同期済み** になり、未送信が残っていないことを確認します。
8. 同期版のスマホへ同じメモとカテゴリが表示されることを確認します。

**復元は共有先の現在の内容を置き換えます。** 共有データがすでにある場合は先に同期版もバックアップし、ほかの端末で編集していない状態で行います。複数のバックアップを合体する機能ではありません。移行が確認できるまで旧アプリを削除しません。

旧PCツールの履歴がある場合は、同期版で **別の新しいリポジトリ名** を使います。旧公開先を上書きする更新ツールではありません。スマホ用ページだけの追加では、旧端末内版に同期機能は付きません。

## 8. 第三者が導入できたことを確認する

導入する本人のSupabase・公開先・メールアドレスで確認します。作者のプロジェクトで代用しません。

| 番号 | 操作 | 合格となる結果 | 結果・日付 |
| --- | --- | --- | --- |
| 1 | PCでメールのコードを使ってログイン | 自分のメールと同期状態が表示される | |
| 2 | スマホのホーム画面から同じメールでログイン | 同じアカウントの内容が表示される | |
| 3 | PCでカテゴリ「確認用」とメモ「PCから確認」を保存 | スマホにも自動で表示される | |
| 4 | スマホでメモの説明を変更 | PCにも変更が反映される | |
| 5 | スマホから新しいメモを追加 | PCにも表示される | |
| 6 | PCから画像付きの操作項目を保存 | スマホに画像・説明が表示される | |
| 7 | スマホでメモを削除 | PCの一覧からも消える | |
| 8 | PC・スマホを閉じて開き直す | 同じ内容が残る | |
| 9 | 読み込み済みのスマホで通信を切り、編集・保存 | 端末に残り、未送信になる | |
| 10 | 未送信のまま閉じて開き直し、通信を戻す | 送信され、PCにも反映される | |
| 11 | 同じメモをオフラインのスマホとオンラインのPCで別々に編集し、スマホをオンラインにする | 競合の選択を表示し、勝手に上書きしない | |
| 12 | 別のメールでログイン | 元の利用者のメモが見えない | |

変更通知が届かない場合でも、アプリを開いたまま少し待つか **同期を再確認** を使います。通信を切った確認の後はWi-Fi・モバイル通信を元へ戻します。

「公開完了」や案内の確認チェックだけでは、実際のインストール・保存・同期が成功したとは判断しません。上の結果を確認します。

## 9. 通信エラーと変更の競合

- **未送信**：変更は端末に保存されています。通信とログインを確認し、アプリを開いて送信を待ちます。
- **取得できない**：その端末で以前取得した内容を表示しています。最新とは限りません。
- **別端末でも変更されている**：先に **バックアップする** を使います。その後 **共有先の内容を使う** または **この端末の内容を反映する** を選び、確認画面で進めます。
- **ログアウト**：未送信がある場合は確認を表示します。同じアカウントへの再ログインで送信を再開します。別アカウントへ未送信データを送ることはありません。

競合の選択はその端末の未送信データに対して行います。共有先を選ぶと、その端末の未送信内容を破棄します。この端末を選ぶと、共有先の同じ項目を更新し、ほかの端末にも反映します。

## 10. うまくいかない場合

| 症状 | 確認すること |
| --- | --- |
| Supabaseの初期設定を確認できない | 自分のProject URL・公開キー・SQL実行結果を確認。停止中のプロジェクトは管理画面で復帰。 |
| SQLで既存ポリシーのエラー | 新しい専用プロジェクトを使う。作者や別アプリの設定を削除して通そうとしない。 |
| 既存リポジトリを使えない | 新しい名前にする。この版の途中処理は前回と同じ入力で再試行。 |
| 公開URLが404 | Actionsの公開完了とSettings → PagesのURLを確認。ローカルのZIPは公開URLではない。 |
| 端末内の試作モードが表示される | 旧版や別URLを開いていないか、同期版の公開と設定を確認。 |
| 確認コードが届かない | メール・迷惑メール・送信制限・SMTP設定を確認。 |
| メールにリンクしかない | Confirm signupとMagic Linkに `{{ .Token }}` を設定。 |
| コードが8桁 | 修正版はそのまま全部入力。以前の6桁用アプリではEmail OTP lengthを6にし、再送した新しいコードを使う。 |
| PCのメモがスマホに出ない | 公開URL・Project URL・メールが同じか、PCが未送信でないか、旧データを移行したか確認。 |
| 変更がすぐ出ない | アプリを表示状態にし、通信を確認して約15秒待つ。Realtime・SQL設定も確認。 |
| オフラインで初回ログインできない | 最初はオンラインでログインし、データを取得する。 |
| 未送信が続く・端末に保存できない | 同期エラー・Supabase状態・端末の空き容量を確認。先にバックアップする。 |

## 11. 費用・バックアップ・確認した範囲

Supabaseは無料プランから始められます。保存容量・通信量・メール送信サービスの料金を確認します。画像はメモ内へ保存するため、SupabaseのDB容量を使います。[Supabaseの料金](https://supabase.com/pricing)

無料プロジェクトは、利用が少ない状態が約7日続くと一時停止される場合があります。停止中は同期できないため管理画面で復帰します。[公式の停止条件](https://supabase.com/docs/guides/platform/free-project-pausing)

定期的に **設定 → バックアップ** でJSONを保存します。復元は共有データの置き換えです。未送信を含む端末の内容をバックアップできますが、削除操作や同期内部の履歴を完全に復元するファイルではありません。

この改訂では、PC画面の生成、入力・管理者用キーの拒否、公開処理の模擬確認、生成アプリのTypeScript・PWAビルド、スマホの入力処理を確認しています。端末保存・送信再開・アカウント分離・競合の選択も、保存領域と共有先を模擬して確認しています。

**実際の第三者のSupabaseへのSQL実行・メール配送・PCとiPhone実機の双方向同期は未確認です。** 導入者の設定を使い、第8章で結果を確認します。今回、作者のSupabaseの設定やデータを変更する操作は行っていません。ツールを作成しただけでは既存の公開先へ自動反映されません。
